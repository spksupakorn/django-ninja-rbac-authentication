Lesson 21 · 18 minutes

เมื่อไร feature จึง “เสร็จ”?

Phase 1 ไม่จบเมื่อ endpoint ตอบ 200 บนเครื่องเรา แต่จบเมื่อ behavior สำคัญมี test, code ผ่าน quality checks ใน CI และ production settings ไม่เปิดช่องโหว่พื้นฐาน

1. Unit tests: ตรวจ logic เป็นชิ้นเล็ก

tests/unit/
  test_passwords.py
  test_jwt.py
  test_auth_service.py

Unit test เรียก function/service โดยตรงและเน้น cases ที่มีความเสี่ยงสูง:

  • password hash แล้ว verify ถูก/ผิด
  • JWT encode/decode, token หมดอายุ, token ถูกแก้
  • refresh rotation happy path และ reuse detection revoke ทั้ง family
  • register assign default role, login ผิดตอบ domain error เดียว

แผนตั้งเป้า service coverage อย่างน้อย 90% เพราะ service เก็บ policy สำคัญที่สุด

2. Integration tests: ตรวจส่วนที่ต่อกัน

tests/integration/
  test_auth_endpoints.py
  test_admin_permissions.py

Integration test ยิง HTTP request ผ่าน API จริงและใช้ test database. มันพิสูจน์ว่า routing, schemas, auth guard, exception handler และ repository เชื่อมกันถูกต้อง—not just function เดี่ยว ๆ

ไม่มี token            → 401
token valid ไม่มี perm → 403
เกิน throttle          → 429
register → login → admin request → behavior ตาม permission

3. Factories: สร้าง test data ที่มีความหมาย

user = UserFactory()
admin = UserFactory()
RolePermissionFactory(role=admin_role, permission=USERS_READ)

factory-boy ช่วยสร้าง User/Role/Permission relationships โดยไม่ต้อง copy-paste setup ยาว ๆ ในทุก test. Test จึงอ่านว่า “กำลังพิสูจน์อะไร” มากกว่า “กำลังเตรียม database อย่างไร”

4. CI คือเครื่องตรวจซ้ำที่ไม่ลืม

uv run ruff check .
uv run mypy
uv run pytest

Ruff: syntax, common bugs และ style

mypy: ความสอดคล้องของ type hints

pytest: behavior ที่เราตั้งใจให้ระบบทำ

CI รันชุดเดียวกันทุก pull request/commit เพื่อไม่ให้คุณภาพขึ้นกับว่าใครจำรันคำสั่งก่อน merge ได้หรือไม่

5. Production settings ต้องเข้มกว่า dev

# config/settings/prod.py
DEBUG = False
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_HSTS_SECONDS = 31_536_000
  • DEBUG=False: ไม่ส่ง debug traceback/config ที่ละเอียดให้ client
  • ALLOWED_HOSTS: จำกัด host headers ที่ Django ยอมรับ
  • secure cookies/HTTPS redirect/HSTS: ลดการส่ง credential ผ่าน HTTP และบังคับ HTTPS behavior
หลัก: dev settings ทำให้พัฒนาได้สะดวก; prod settings ลด attack surface. อย่าใช้ค่า `.env.example` หรือ JWT secret ตัวอย่างใน deployment จริง
