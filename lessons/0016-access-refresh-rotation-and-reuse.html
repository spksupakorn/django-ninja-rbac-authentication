ทำไมต้องมี token สองชนิด?

Access token ต้องอายุสั้นเพราะถูกส่งบ่อย; refresh token อยู่ได้นานกว่าเพื่อขอ access token ใหม่โดยไม่ต้องให้ผู้ใช้ใส่ password ทุก 15 นาที. ความเสี่ยงของ refresh token จึงต้องควบคุมเข้มกว่า

Access vs refresh

Access token: JWT ที่ signed, อายุ 15 นาที, ส่งใน Authorization: Bearer ..., มี roles/perms snapshot สำหรับ guard

Refresh token: credential อายุ 7 วัน, ใช้เฉพาะขอคู่ token ใหม่, มี state ใน database เพื่อ revoke และตรวจ reuse

Access token ออกแบบให้ตรวจ signature/expiration ได้เร็ว. Refresh token ต้อง query database เพราะต้องรู้ว่าถูก revoke ไปหรือยัง

RefreshToken model เก็บอะไร?

RefreshToken
  user
  token_hash
  family_id
  parent_id
  expires_at
  revoked_at
  • token_hash: hash ของ raw refresh token; database ไม่เก็บ raw token
  • family_id: กลุ่ม tokens ที่เริ่มจาก login session เดียวกัน
  • parent_id: token ก่อนหน้าที่ถูก rotate มาเป็น token นี้
  • revoked_at: มีค่าเมื่อ token ใช้ต่อไม่ได้แล้ว

Login สร้าง family ใหม่

login สำเร็จ
  → access token A1
  → refresh token R1
  → family F1
  → database เก็บ hash(R1), family=F1, revoked_at=None

หนึ่ง login session มี family ของตัวเอง จึง revoke แยก session ได้ในอนาคต

Rotation: refresh ที่ถูกต้อง

client ส่ง R1
  → DB พบ hash(R1), ยังไม่หมดอายุ, ยังไม่ revoked
  → revoke R1
  → ออก access A2 + refresh R2
  → DB เก็บ hash(R2), family=F1, parent=R1

หลัง rotation, R1 ใช้ซ้ำไม่ได้. Client ต้องแทนที่ refresh token เก่าด้วย R2 เสมอ

Reuse detection: refresh เก่าถูกส่งอีกครั้ง

attacker หรือ client เก่าส่ง R1 อีกครั้ง
  → DB พบ R1 แต่ revoked แล้ว
  → ถือว่า token reuse
  → revoke tokens ทั้ง family F1
  → response ล้มเหลว; ต้อง login ใหม่
เหตุผล: server แยกไม่ออกว่าใครเป็นเจ้าของ R1 ที่แท้จริง. การ revoke ทั้ง family จำกัดความเสียหายหาก token เก่าถูกขโมย แม้จะทำให้ session ปัจจุบันที่ใช้ R2 ต้อง login ใหม่ด้วย

Logout ทำอะไร?

Logout รับ raw refresh token, หา record ด้วย hash แล้วตั้ง revoked_at ของ token นั้น. Access token อาจใช้ได้จนหมดอายุตามธรรมชาติ (สูงสุด 15 นาที) เพราะเป็น signed token ที่ไม่ได้ query database ทุก request
