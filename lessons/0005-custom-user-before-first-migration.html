ทำไม User model เป็น “ประตูทางเดียว”?

Django มี User model มาตรฐานให้ แต่โปรเจกต์นี้ต้อง login ด้วย email และไม่ต้องการ username. เราจึงเลือก custom user model ก่อน database schema ของเราเริ่มถูกสร้าง

User model คืออะไร?

Model คือ Python class ที่ Django map ไปยัง database table. User model คือ model พิเศษสำหรับตัวตนที่ login ได้; Django auth, admin, permission และ model อื่น ๆ จะอ้างอิงมัน

Default: Django ใช้ auth.User ซึ่งมี username

โปรเจกต์นี้: จะใช้ accounts.User และ email เป็น identity หลัก

สิ่งที่ M1 จะสร้าง

apps/accounts/
  models.py       # class User(AbstractBaseUser, PermissionsMixin)
  managers.py     # UserManager.create_user / create_superuser
  migrations/

config/settings/base.py
  AUTH_USER_MODEL = "accounts.User"
  • AbstractBaseUser ให้พื้นฐาน password hashing และ authentication behavior โดยไม่บังคับ field username
  • PermissionsMixin เพิ่ม flags/relations ที่ Django ใช้กับ groups, permissions และ superuser
  • UserManager กำหนดวิธีสร้าง user ให้ validate และ normalize email สม่ำเสมอ
  • USERNAME_FIELD = "email" บอก Django ว่า email คือ identifier ตอน login/createsuperuser

ทำไมต้องก่อน migration แรก?

Migration คือประวัติคำสั่งที่เปลี่ยน database schema. เมื่อ migration เริ่มมี foreign key ไปที่ user model Django ต้องรู้ว่าปลายทางคือ model ใดแล้ว

ตั้ง AUTH_USER_MODEL = "accounts.User"
สร้าง initial migration ของ accounts
migrate สร้าง table ของ custom User
M2 เช่น UserRole อ้างอิง user model เดียวกัน
ถ้าตั้งช้า: database อาจมี foreign key และ migrations ที่ผูกกับ auth.User ไปแล้ว การสลับไป accounts.User ต้องย้าย schema/data/relations อย่างระมัดระวัง จึงควรตัดสินใจตอนเริ่มต้น

การอ้างอิง user ในอนาคต

# ใน model อื่น (เช่น RefreshToken ในอนาคต)
user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)

อย่า hard-code auth.User. การอ้างผ่าน settings.AUTH_USER_MODEL ทำให้ทุก relation ชี้ไปยัง user model ที่โปรเจกต์เลือกไว้

ลองอธิบายกลับ

สมมติ M2 จะเพิ่ม UserRole ที่เชื่อม User กับ Role. ถ้า M1 ใช้ default auth.User ไปแล้ว แต่ต่อมาอยากเปลี่ยนเป็น accounts.User, relation ของ UserRole จะมีความเสี่ยงอะไร?
