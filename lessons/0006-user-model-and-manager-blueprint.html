Lesson 6 · 15 minutes

ใครสร้าง User อย่างปลอดภัย?

`User` อธิบายข้อมูลและความสามารถของคนหนึ่งคน; `UserManager` เป็นประตูมาตรฐานที่สร้าง User พร้อม validate email และ hash password ถูกวิธี

แบ่งหน้าที่ก่อน

User = model/table และ fields ของผู้ใช้หนึ่งคน
UserManager = วิธีสร้าง user และ superuser อย่างสม่ำเสมอ
AUTH_USER_MODEL = บอก Django ให้ใช้ User model นี้

Blueprint ของ User

class User(AbstractBaseUser, PermissionsMixin):
    email = models.EmailField(unique=True)
    is_active = models.BooleanField(default=True)
    is_staff = models.BooleanField(default=False)

    objects = UserManager()

    USERNAME_FIELD = "email"
    REQUIRED_FIELDS = []

นี่คือ design ที่ M1 จะ implement; ตอนนี้ไฟล์ models.py ยังไม่มี เพราะเราอยู่ใน M0 skeleton

  • email(unique=True): database บังคับว่าห้ามมี account สองบัญชีใช้ email เดียวกัน
  • is_active: ใช้ปิดการใช้งาน account โดยไม่ต้องลบข้อมูล
  • is_staff: ระบุว่าเข้า Django admin site ได้หรือไม่
  • USERNAME_FIELD: เปลี่ยนความหมายของ “username” ในระบบ auth ให้เป็น email
  • REQUIRED_FIELDS: fields เพิ่มที่ `createsuperuser` ต้องถาม; email อยู่ใน `USERNAME_FIELD` แล้วจึงไม่ใส่ซ้ำ

Base classes ให้สิ่งใด?

AbstractBaseUser ให้ส่วนพื้นฐานของ password เช่น field password, set_password(), check_password(), และ last_login

PermissionsMixin ให้ is_superuser, groups, user permissions และ methods ตรวจสิทธิ์

สังเกตว่า is_staff ไม่ได้มาจากสอง base class นี้ จึงต้องประกาศใน custom model เองเพื่อใช้กับ admin

UserManager ทำไมสำคัญ?

class UserManager(BaseUserManager):
    def create_user(self, email, password, **extra_fields):
        if not email:
            raise ValueError("Email is required")
        user = self.model(email=self.normalize_email(email), **extra_fields)
        user.set_password(password)
        user.save(using=self._db)
        return user

ประเด็นสำคัญไม่ใช่ syntax แต่เป็นลำดับ:

ตรวจว่า email มีอยู่
normalize email เพื่อเก็บอย่างสม่ำเสมอ
set_password(raw_password) สร้าง hash
save user
ห้าม: เขียน user.password = raw_password. วิธีนั้นเก็บรหัสผ่านจริงใน database และ Django จะ login ไม่ได้อย่างถูกต้อง. ต้องใช้ set_password() เสมอ

Superuser เป็น user ที่มี flags เพิ่ม

def create_superuser(self, email, password, **extra_fields):
    extra_fields.setdefault("is_staff", True)
    extra_fields.setdefault("is_superuser", True)
    return self.create_user(email, password, **extra_fields)

implementation จริงควรตรวจด้วยว่า caller ไม่ได้ส่ง is_staff=False หรือ is_superuser=False. จึงมั่นใจได้ว่า superuser มีสิทธิ์ตามชื่อ

Quiz: ต้องใช้ method ใดก่อนบันทึก password ของ User?

A = save() · B = normalize_email() · C = set_password()
