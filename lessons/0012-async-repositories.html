Repository คือขอบเขตของ database

เมื่อ endpoint เป็น async def, database query เป็น I/O ที่ต้องรอ. โปรเจกต์นี้รวม query ไว้ใน repository และใช้ async ORM methods เพื่อให้ service ไม่ต้องรู้รายละเอียดนั้น

ตัวอย่าง repository

class AccountsRepository:
    async def aget_by_email(self, email: str) -> User | None:
        return await User.objects.filter(email=email).afirst()

class AuthzRepository:
    async def acreate_permission(self, code: str) -> Permission:
        return await Permission.objects.acreate(code=code)

ชื่อขึ้นต้น a ช่วยสื่อว่า method เป็น async และ caller ต้องใช้ await. การออกแบบจริงอาจใช้ method names ต่างกันได้ แต่ responsibility ยังอยู่ที่ repository เดียวกัน

ข้อยกเว้นของ User: repository ไม่ควรสร้าง User ด้วย acreate(password=raw_password); M1 ใช้ UserManager.create_user() เพื่อ hash password ก่อนบันทึก

filter() ยังไม่ query เสมอไป

queryset = User.objects.filter(email=email)  # สร้างคำอธิบาย query
user = await queryset.afirst()               # ตรงนี้จึง query database

QuerySet เป็น lazy: filter() สร้างแผนว่าจะหาอะไร แต่ operation ที่ต้องอ่าน/เขียน database เช่น aget(), afirst(), acreate() คือจุดที่ต้อง await ใน async code

Sync กับ async ORM

Sync: User.objects.get(email=email)

Async: await User.objects.aget(email=email)

หากเรียก sync ORM ที่ execute ใน async context Django อาจ raise SynchronousOnlyOperation; ถึงบางกรณีจะไม่ error ก็เสี่ยง block event loop. เราจึงใช้ async variant ตาม ADR 0005

Base repository ช่วยอะไร?

class BaseAsyncRepository:
    async def aget_or_none(...): ...
    async def acreate(...): ...

class AccountsRepository(BaseAsyncRepository): ...
class AuthzRepository(BaseAsyncRepository): ...

method ทั่วไปอยู่ใน base class เพื่อลด code ซ้ำ; query ที่เฉพาะ domain เช่น “หา user ด้วย email” อยู่ใน repository ของ app นั้น

เส้นทางจาก service

# service ใช้ภาษาของ business use case
user = await accounts_repository.aget_by_email(email)
if user is None:
    raise InvalidCredentials

Service ไม่ต้องรู้ว่าใช้ PostgreSQL, QuerySet หรือ filter อย่างไร; repository เป็นคนแปลความต้องการ “หา user ด้วย email” เป็น ORM query

Quiz: ใน async repository วิธีใดเหมาะสำหรับหา User หนึ่งคนจาก email?

A = await User.objects.aget(...) · B = User.objects.get(...) · C = await User.objects.filter(...)

ลองอธิบายกลับ

เหตุใด User.objects.filter(email=email) จึงยังไม่ต้อง await แต่ await queryset.afirst() ต้องใช้? ตอบโดยแยกว่าแต่ละบรรทัดทำงานกับ database หรือยัง
