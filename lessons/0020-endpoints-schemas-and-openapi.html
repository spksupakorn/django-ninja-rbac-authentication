Router คือ API contract ไม่ใช่ business logic

M7 นำ use cases ของ AuthService มาเปิดเป็น HTTP endpoints. Django Ninja schema รับผิดชอบ validate input และ serialize output, ส่วน router เรียก service และบอก auth/permission ที่ route ต้องการ

Pydantic schema ทำหน้าที่อะไร?

class RegisterIn(Schema):
    email: str
    password: str

class TokenPairOut(Schema):
    access_token: str
    refresh_token: str
    token_type: str = "bearer"
  • Input schema: ตรวจรูปร่างและชนิดของ JSON ก่อนส่งให้ service
  • Output schema: กำหนด fields ที่ client ได้รับ และช่วยสร้าง OpenAPI documentation
  • สำคัญ: อย่าส่ง Django User model ตรง ๆ เพราะอาจเผลอ expose password hash หรือ internal fields

Router ที่บางมีหน้าตาแบบใด?

@router.post("/login", response=TokenPairOut)
async def login(request, payload: LoginIn):
    return await auth_service.login(payload.email, payload.password)

Router รับ validated payload, เรียก service, แล้ว Ninja serialize output ตาม schema. เมื่อ service raise InvalidCredentials, exception handler กลางจะตอบ 401

Admin endpoints ต้องมี permission

GET  /admin/users                 → users.read
POST /admin/users/{id}/roles      → roles.assign
GET  /admin/roles                 → roles.read
GET  /admin/permissions           → permissions.read

Admin ไม่ได้แปลว่า endpoint ใต้ prefix /admin/ จะปลอดภัยเอง. ทุก route ต้องใช้ JWTAuth และ require_permission(...) ที่ตรงกับ action

Pagination คือส่วนของ contract

List endpoints เช่น users, roles และ permissions ต้องมี pagination. Client จึงรู้ว่าจะขอ page/limit อย่างไร และ response บอก items กับ metadata ที่แน่นอน แทนการคืนทุก record จน response โตไม่จำกัด

OpenAPI ได้มาฟรีจาก schema/routes

NinjaAPI()
  → /api/openapi.json  # machine-readable contract
  → /api/docs          # interactive documentation

เมื่อ annotation และ schemas ถูกต้อง Ninja สร้าง API docs ได้. ตอนนี้ M0 มี docs root แล้ว; M7 จะทำให้ auth/admin endpoints ปรากฏในหน้านั้น
