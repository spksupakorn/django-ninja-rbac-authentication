Lesson 7 · 12 minutes

Model เปลี่ยน database ได้อย่างไร?

Django ไม่เปลี่ยน PostgreSQL ทันทีเมื่อเราแก้ Python class. เราสร้าง migration file ที่เป็นประวัติ schema ก่อน แล้วจึง apply ประวัตินั้นกับ database

สองคำสั่ง สองหน้าที่

python manage.py makemigrations อ่านการเปลี่ยนแปลงใน models.py แล้ว เขียน Python migration file ลง repository

python manage.py migrate อ่าน migration files ที่ยังไม่ apply แล้ว เปลี่ยน schema ใน database

models.py
  ↓
makemigrations
  ↓
apps/accounts/migrations/0001_initial.py
  ↓
migrate
  ↓
PostgreSQL tables
เปรียบเทียบ: makemigrations คือเขียนแบบแปลนและเก็บใน Git; migrate คือช่างสร้างตามแบบแปลนใน database

ทำไม M0 มีโฟลเดอร์ migrations แล้ว?

apps/accounts/migrations/__init__.py ทำให้ Django มอง migrations/ เป็น Python package. ตอน M1 เมื่อมี User model, Django จะสร้างไฟล์แรก เช่น 0001_initial.py ไว้ตรงนี้

ลำดับปลอดภัยของ M1

เพิ่ม User และ UserManager ใน accounts
ตั้ง AUTH_USER_MODEL = "accounts.User" ใน settings
รัน makemigrations accounts
review accounts/migrations/0001_initial.py
รัน migrate บน PostgreSQL

เหตุผลที่ setting มาก่อน migration: migration ของ app อื่นในอนาคตจะอ้างอิง user model ที่ถูกเลือกแล้วตั้งแต่ต้น

ไฟล์ migration มีไว้ทำอะไร?

# ตัวอย่างแนวคิด ไม่ใช่ไฟล์จริงของโปรเจกต์
migrations.CreateModel(
    name="User",
    fields=[
        ("id", models.BigAutoField(...)),
        ("email", models.EmailField(unique=True)),
        ...
    ],
)

ไฟล์นี้เป็น Python code ที่บรรยาย schema เป้าหมาย. ต้อง commit มันพร้อมกับ model change เพื่อให้ teammate, CI และ production database เปลี่ยน schema แบบเดียวกัน

คำสั่งช่วยตรวจ

# แสดง migration ทั้งหมดและสถานะว่า apply แล้วหรือยัง
uv run python manage.py showmigrations

# ตรวจว่า model change มี migration ที่ลืมสร้างหรือไม่
uv run python manage.py makemigrations --check --dry-run

ตอนนี้ M0 ยังไม่มี model ของเรา จึงยังไม่มี accounts/0001_initial.py; นั่นเป็นปกติ

Quiz: คำสั่งใดเปลี่ยน PostgreSQL schema จริง?
