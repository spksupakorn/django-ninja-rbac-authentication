ใครบอก Django ว่า URL อยู่ที่ไหน?

คำตอบคือ settings. ส่วน urls.py คือแผนที่ และ api.urls คือแผนที่ย่อยที่ Django Ninja สร้างให้

1. Settings เลือก URL map หลัก

# config/settings/base.py
ROOT_URLCONF = "config.urls"

ชื่อนี้เป็น Python import path ไม่ใช่ path บน disk: Django จึง import module config.urls แล้วมองหาตัวแปรชื่อ urlpatterns ในนั้น

เปรียบเทียบ: ROOT_URLCONF คือบอกตำแหน่ง “สมุดแผนที่หลัก”; urlpatterns คือรายการเส้นทางในสมุดนั้น

2. config/urls.py เลือก prefix

# config/urls.py
urlpatterns = [
    path("admin/", admin.site.urls),
    path("api/", api.urls),
]

path("api/", api.urls) ไม่ได้เรียก endpoint โดยตรง แต่มันพูดว่า “ถ้า URL เริ่มด้วย /api/ ให้ส่งส่วนที่เหลือให้ Ninja API นี้จัดการ”

3. api.urls คืออะไร?

# config/api.py
api = NinjaAPI()

@api.get("/health")
async def health(request):
    return {"status": "ok"}

api เป็น object ของ NinjaAPI. Attribute api.urls แปลง routes ที่ประกาศด้วย decorator เช่น @api.get เป็น Django URL patterns ที่ Django เข้าใจได้

ROOT_URLCONF = "config.urls"
path("api/", api.urls) จับ prefix /api/
@api.get("/health") จับส่วนที่เหลือ /health
รวมเป็น GET /api/health

กฎสำคัญ: prefix + route

การประกอบ URL เกิดจากการต่อ string สองชั้น:

"api/"     + "/health"  =  "/api/health"

แม้ string แรกไม่มี slash ด้านหน้า (ตาม convention ของ Django) และ string ที่สองมี slash ด้านหน้า ผลลัพธ์ URL สำหรับ browser คือ /api/health

A = ASGI_APPLICATION · B = ROOT_URLCONF · C = INSTALLED_APPS

ลองตรวจด้วยตัวเอง

เปิด config/settings/base.py แล้วหา ROOT_URLCONF; ต่อด้วย config/urls.py แล้วหา path("api/", ...). ถ้าคุณเปลี่ยน prefix เป็น v1/ (อย่าเพิ่งแก้จริง) URL ของ health จะกลายเป็นอะไร?

แหล่งหลัก: Django URL dispatcher และ Django settings

ตอบคำถามท้ายบทมาได้เลย แล้วผมจะตรวจ reasoning ให้ ก่อนพาไปดู Settings(BaseSettings) และ environment variables
