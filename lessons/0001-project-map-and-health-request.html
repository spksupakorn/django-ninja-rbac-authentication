Lesson 1 · 10 minutes

ตามรอย request หนึ่งครั้ง

เป้าหมายวันนี้: อธิบายได้ว่า GET /api/health วิ่งผ่านไฟล์ใดบ้างก่อนตอบ {"status": "ok"} นี่คือแผนที่ที่ใช้อ่านทุก feature ต่อจากนี้

ภาพรวมก่อนเปิดไฟล์

Uvicorn
config/asgi.py
config/settings/dev.py → base.py
config/urls.py
config/api.py

อย่าจำเป็นรายไฟล์ ให้จำหน้าที่: เริ่ม server → โหลดกติกา → เลือก URL → ทำ endpoint

เปิดตามลำดับนี้

  1. config/asgi.py สร้าง callable ชื่อ application; Uvicorn เรียกมันเมื่อรับ HTTP request
  2. config/settings/base.py อ่าน environment, ตั้ง ROOT_URLCONF = "config.urls"
  3. config/urls.py มี path("api/", api.urls); ทุก path ที่ขึ้นต้น /api/ ถูกส่งให้ Django Ninja
  4. config/api.py มี @api.get("/health"); Ninja จับคู่ส่วนท้าย /health แล้วเรียก function health
จุดที่มักสับสน: api/ อยู่ใน Django URL config แต่ /health อยู่ใน Ninja API. ต่อกันแล้วจึงเป็น /api/health และตามค่าเริ่มต้น Ninja ใช้ URL ไม่มี trailing slash

ลองทำเอง (2 นาที)

โดยไม่ดูคำตอบ: URL /api/health ถูกประกอบจาก สอง string ใด และอยู่ในไฟล์ใดบ้าง?

เปิดเฉลยหลังลองตอบ

"api/" ใน config/urls.py + "/health" ใน config/api.py

Quiz: เมื่อ Uvicorn รับ request ไฟล์ใดเป็น entry point?
